# 주문 생성 로직 상세 (OrderCommandService)

## 1) 전체 흐름 개요
1. 요청 검증 및 커맨드 생성
2. 가격 조회(캐시 우선, miss 시 fallback)
3. 사용자 주소 조회(캐시 hit만 사용, miss는 비동기 보강)
4. 주문 엔티티 생성 및 저장
5. 예약/재고 요청 이벤트 발행
6. 예약 응답 대기(현재는 동기 대기 유지)
7. 결과에 따라 상태 변경 및 응답 생성

---

## 2) 분기 로직
### (A) 예약 전용 주문
- schedule 예약 요청 발행
- 예약 성공 → PAYMENT_PENDING 전환 → 결제 생성 요청
- 예약 실패/타임아웃 → CANCELLED

### (B) 굿즈 전용 주문
- goods 재고 예약 요청 발행
- 예약 성공 → PAYMENT_PENDING 전환 → 결제 생성 요청
- 예약 실패/타임아웃 → CANCELLED

### (C) 복합 주문(MIXED)
- 스케줄 예약 요청 먼저
- 스케줄 성공 시 굿즈 재고 예약 요청
- 두 예약 모두 성공 시 PAYMENT_PENDING 전환

---

## 3) 주요 예외 처리
- 예약 응답 타임아웃
  - 주문 CANCELLED 처리
  - idempotency 키 무효화
- 예약 실패 이벤트
  - 주문 CANCELLED 처리
- 결제 생성 실패
  - 기본 응답/재시도 경로로 분기

---

## 4) 성능 최적화 포인트
- 가격 조회 timeout 축소 (200ms)
- 주소 조회 캐시 hit만 사용
- 이벤트 발행은 DB 커밋 후 처리
- 예약 응답 대기 최소화
